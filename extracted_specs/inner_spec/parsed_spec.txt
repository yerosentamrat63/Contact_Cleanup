Contact Cleaner: build spec
This page is the single source of truth for building the app. The eight 390×844 artboards on this canvas show how every screen looks. This page explains everything the pictures cannot: exact values, motion, behavior and state. Where this page and an artboard disagree, ask; do not guess. Artboard HTML is plain inline CSS and can be read for exact values.
1. What the app does
Contact Cleaner shows the user's phone contacts one at a time as a swipeable card. Swipe right to mark a contact for deletion, swipe left to keep it. After the last contact the user sees a review list of everything marked, can untick any, and confirms once. Only then are contacts actually deleted. Nothing is deleted before that final confirmation.
Target:
Flutter (Android and iOS). 1 CSS px in the artboards = 1 logical pixel (dp). Reference frame is 390×844; layouts must adapt to other sizes by letting the card area flex (see Swipe screen).
Existing code:
main.dart
already implements the logic (stages: loading, denied, swiping, reviewing, done; package
flutter_contacts
; decisions, undo, review, delete). Keep that logic. Replace its look with this design, and add onboarding, the coach mark, the confirm sheet and the animations below.
Packages:
flutter_contacts
,
google_fonts
(Bricolage Grotesque, JetBrains Mono),
shared_preferences
(remember that onboarding and the coach mark were seen).
All names, numbers and emails in the artboards are placeholders.
The real app reads the device contact list, sorted by display name, A to Z. The first sample contact has two numbers on purpose: it illustrates a merged contact, which is the problem this app exists to solve. The card must list every number and email a contact has.

Background texture
Every screen has a subtle two-layer texture over the Bone color, meant to feel like dark wood grain seen through paper. In the HTML it is an SVG noise filter, which Flutter cannot use directly. Recreate it as a tileable PNG (or a fragment shader) drawn once behind all content and never above it:
Layer A, streaks:
horizontal fractal noise, stretched about 60× wider than tall (base frequency 0.006 horizontally, 0.35 vertically), 3 octaves, colored olive-grey
#57554B
, layer opacity about 0.2.
Layer B, grain:
fine fractal noise (frequency 0.85, 2 octaves), colored near-black
#121210
, layer opacity about 0.4, thresholded so only the brighter noise specks show and the rest is transparent.
Result should read as barely-there speckle and faint horizontal banding. Text must stay fully readable. Cards sit on top of the texture and are solid, with no texture on them.

6. Behavior and state
State to keep:
the contact list (sorted), current index, a decisions list (one boolean per decided contact, true = delete), the set of unchecked contact ids on Review, the stage, the deleted count, and persisted flags for “onboarding seen” and “coach seen”.
Decide:
swiping right or tapping Delete records true; swiping left or tapping Keep records false. After the last contact, go to Review. Review lists exactly the contacts with true, in their original order.
Undo:
removes the last decision, steps back one contact, clears Review's unchecked set, and goes to Swipe (this also covers the back button on Review).
Delete:
on confirm, delete only contacts that are marked and still checked, using the full contact object from the device list. Show Done with that number. Kept on Done = total minus deleted.
Permission:
request read and write access on first need. If it is denied or later revoked, show the Permission screen. An empty contact list goes straight to Done with “Nothing deleted”.
Never
delete anything before the confirm sheet's Delete button is tapped.

8. Accessibility checklist
Every icon-only button has a semantic label: “Undo last swipe”, “Keep contact”, “Mark contact for deletion”, “Back to swiping”.
Swiping is never the only way to decide: the Keep and Delete buttons always work, and screen-reader users can use them.
Announce decisions (for example “Marked Dawit Alemu for deletion”) and the new position.
Minimum touch target 44×44; text contrast at or above 4.5:1 using the colors in this spec; no meaning is carried by color alone (stamps and labels use words and icons as well).
Keep the focus ring on Review checkboxes and the coach button visible.
9. Done when
All eight screens match the artboards at 390×844 for colors, type, spacing and copy.
